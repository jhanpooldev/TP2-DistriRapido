# Documento 05: Evaluación e Identificación del Stack Tecnológico

**Proyecto:** EcoLogística Lima – Optimizador de Rutas Sostenibles para DistriRápido S.A.C.
**Versión:** 1.0.0 | **Fecha:** 27/08/2026

---

## 1. Introducción y Criterios de Evaluación

El presente documento evalúa y selecciona el conjunto de tecnologías (stack) más adecuado para construir el sistema **EcoLogística Lima**. El objetivo es garantizar que la tecnología elegida permita implementar el módulo de optimización de rutas de forma eficiente, mantenga un costo de infraestructura nulo (acorde al presupuesto de S/ 0.00 definido en el Acta de Constitución) y ofrezca una curva de aprendizaje razonable para el equipo, integrado por estudiantes de décimo ciclo con un plazo de desarrollo de tres meses. Una selección inadecuada podría comprometer la entrega del Producto Mínimo Viable (PMV), razón por la cual se evalúan de forma objetiva tres alternativas viables.

La evaluación considera criterios multidimensionales: la **curva de aprendizaje** (tiempo necesario para que el equipo domine la tecnología), el **costo de infraestructura** (recursos exigidos en el hosting gratuito), el **soporte comunitario** (disponibilidad de documentación y ayuda), la **eficiencia energética** (consumo de recursos y huella ambiental, alineado con el enfoque de sostenibilidad del proyecto), la **velocidad de desarrollo** (capacidad de entregar el PMV en el plazo) y la **mantenibilidad** (facilidad para corregir y ampliar el código). Con esta matriz se selecciona la alternativa que mejor equilibra la viabilidad técnica, el costo y la capacidad real del equipo.

## 3. Justificación y Selección del Stack Tecnológico Final

### 3.1 Stack Seleccionado

**Alternativa 2: Python / FastAPI + React + PostgreSQL**

Se elige el stack compuesto por **FastAPI** (Backend en Python), **React con Vite** (Frontend), **PostgreSQL** como base de datos (con SQLAlchemy y Alembic), junto con **OR-Tools** para la optimización de rutas, **JWT/bcrypt** para la autenticación y **Tailwind CSS** para la interfaz.

### 3.2 Fundamentación Técnica y de Negocio

1. **Idoneidad técnica para el núcleo del proyecto:** el corazón del sistema es el cálculo de rutas optimizadas. Python es el lenguaje de referencia para algoritmos de optimización y cuenta con **OR-Tools**, una librería madura y de alta calidad para resolver problemas de rutas (TSP/VRP). Implementar este módulo en Python reduce considerablemente el esfuerzo y el riesgo técnico frente a las otras alternativas.

2. **Costo de infraestructura nulo y bajo consumo:** FastAPI es una tecnología asíncrona y de **bajo consumo de memoria y CPU**, lo que la hace ideal para ejecutarse en un hosting gratuito (free tier) sin costos adicionales. Esto cumple directamente el objetivo de presupuesto S/ 0.00 en infraestructura definido en el Acta de Constitución, y refuerza el enfoque de sostenibilidad del proyecto (eficiencia energética).

3. **Velocidad de desarrollo adecuada al plazo:** FastAPI genera automáticamente documentación interactiva (Swagger/OpenAPI), y junto con React/Vite permite construir el PMV rápidamente. El equipo ya definió en el README y SPECS la arquitectura por capas con este stack, lo que elimina trabajo de redefinición y acelera el inicio del desarrollo dentro de los tres meses disponibles.

4. **Mantenibilidad y claridad para estudiantes:** la combinación de Python con tipado (Pydantic) y la separación clara entre backend y frontend produce un código limpio y fácil de mantener. Esto se alinea con la regla de separación de responsabilidades de la consigna y con la capacidad de un equipo universitario de corregir y ampliar funciones sin reescribir todo.

5. **Restricciones del proyecto satisfechas:** el stack cubre el modelado de datos con PostgreSQL/SQLAlchemy, la autenticación con JWT/bcrypt, la validación con Pydantic y las pruebas con pytest (backend) y Vitest/Cypress (frontend), tal como exige el SPECS. Estas tecnologías son de **código abierto y gratuitas**, respetando el presupuesto y los lineamientos del curso.

---

## 4. Conclusión

Tras comparar las tres alternativas, el stack **Python/FastAPI + React + PostgreSQL** es el más equilibrado para EcoLogística Lima: sobresale en el módulo de optimización de rutas, exige el menor costo y consumo de recursos, ofrece la documentación automática que acelera el desarrollo y es mantenible para un equipo de estudiantes. Las alternativas MERN y Java Spring Boot plantean mayores desventajas (menor idoneidad para los algoritmos o mayor complejidad y consumo), por lo que se descartan en favor de la opción seleccionada.
