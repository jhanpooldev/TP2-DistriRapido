# Documento 01: Requisitos Funcionales y Elicitación Holística

**Proyecto:** EcoLogística Lima – Optimizador de Rutas Sostenibles para DistriRápido S.A.C.
**Versión:** 1.0.0 | **Fecha:** 27/08/2026

---

## 1. Marco de Elicitación Holística y Ética

El presente documento establece la especificación de requisitos funcionales del sistema **EcoLogística Lima**, resultado del proceso de elicitación aplicado en la fase de Inicio del proyecto. Dado el carácter académico del proyecto y el plazo limitado de doce semanas, el alcance se ha delimitado a un **Producto Mínimo Viable (PMV)** que prioriza el flujo operativo central: registrar puntos de entrega, calcular una ruta optimizada y visualizarla en un mapa. Este enfoque garantiza que el equipo, integrado por estudiantes de décimo ciclo, pueda entregar una solución funcional y de calidad dentro del tiempo disponible, en lugar de intentar cubrir un espectro artificialmente amplio de funcionalidades.

### Diversidad de Grupos de Usuarios

El proceso de elicitation consideró los actores reales que intervienen en la operación logística de DistriRápido S.A.C. Para el PMV, se priorizan tres perfiles con objetivos diferenciados: el **Operador Logístico**, que ejecuta el flujo principal (registro de puntos y generación de rutas); el **Administrador**, que gestiona usuarios y los datos básicos de la operación; y el **Gerente**, que consulta los resultados e indicadores de las rutas. Cada perfil representa distintos niveles de alfabetización digital y distintas necesidades de interacción, por lo que las interfaces se diseñan para ser claras y directas, con formularios simples y una navegación guiada. La accesibilidad se aborda mediante etiquetas descriptivas, mensajes de error explícitos y estados de carga visibles, asegurando que usuarios con experiencia técnica limitada puedan completar las tareas sin asistencia externa.

### Contexto Local y "Glocal"

El sistema se diseña para operar en Lima Metropolitana, un contexto urbano donde las entregas de última milla deben atravesar zonas con restricciones de tránsito y distancias variables entre el centro de distribución y los puntos de destino. El PMV respeta esta realidad local al considerar el centro de distribución como punto de origen de toda ruta y al estimar distancias y tiempos mediante una API de geolocalización gratuita. A la vez, la solución se construye bajo estándares globales de ingeniería de software —separación de frontend/backend, API REST, versionado semántico, pruebas automatizadas y documentación bajo PMBOK—, de modo que sea mantenible, escalable y extensible a otros contextos en el futuro sin rediseños.

### Perspectiva Ética

Desde el punto de vista ético, el sistema incorpora privacidad por diseño en el tratamiento de datos de acceso: las contraseñas se almacenan mediante hashing irreversible y los datos sensibles solo se exponen al usuario que los generó. La equidad en los flujos se asegura mediante roles de usuario que restringen el acceso a las funciones según responsabilidad, impidiendo que un operador modifique la gestión de otros. La transparencia se refleja en la comparación explícita entre la ruta optimizada y la no optimizada, mostrando al usuario el ahorro de distancia y CO₂ de forma honesta y verificable, sin ocultar resultados. Finalmente, el sistema mitiga sesgos al tratar todas las entregas con reglas uniformes de optimización, priorizando únicamente según criterios configurados y explícitos como la urgencia.

### Metodología de Elicitación

La recolección de necesidades se ejecutó mediante el análisis de los documentos de gestión ya elaborados —Acta de Constitución, Declaración de Visión y SPECS— y del dominio de negocio de la logística de última milla. Los requisitos se derivaron de los cinco RF de alto nivel definidos en el Acta de Constitución (RF-01 a RF-05) y se refinaron en tarjetas atómicas y verificables. Este documento prioriza únicamente lo esencial para que el PMV sea funcional y demostrable, dejando los módulos deseables (gestión avanzada de flota, conductores, reportes complejos) como mejoras post-PMV. Cada requisito se expresa con redacción atomica, verificable e independiente de la implementación, acompañado de criterios BDD que sirven de contrato entre el negocio y el desarrollo.

## 2. Especificación Atómica de Requisitos Funcionales

---

### RF-001: Autenticación de Usuarios (Login)
- **Descripción Atómica:** El sistema debe permitir el acceso a usuarios registrados mediante la validación de correo electrónico y contraseña, otorgando una sesión segura con expiración determinada.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**
  #### Ruta Gold
  DADO que un usuario registrado se encuentra en la página de inicio de sesión
  CUANDO ingresa datos de acceso válidos y presiona "Iniciar Sesión"
  ENTONCES el sistema valida las credenciales y redirige al usuario al panel correspondiente a su rol.

  #### Ruta Feliz
  DADO que un usuario tiene una sesión activa
  CUANDO el período de validez de la sesión expira
  ENTONCES el sistema invalida el acceso y redirige al usuario a la página de inicio de sesión.

  #### Ruta Infeliz
  DADO que un usuario ingresa credenciales incorrectas o un correo no registrado
  CUANDO presiona "Iniciar Sesión"
  ENTONCES el sistema deniega el acceso y muestra el mensaje "Credenciales incorrectas", sin revelar cuál campo erró.

---

### RF-002: Registro de Usuarios
- **Descripción Atómica:** El sistema debe permitir al administrador crear nuevos usuarios con nombre, correo electrónico, contraseña y rol, almacenando la contraseña de forma segura.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**
  #### Ruta Gold
  DADO que un administrador accede al módulo de usuarios
  CUANDO completa el formulario con nombre, correo, contraseña y rol, y confirma
  ENTONCES el sistema crea el usuario y muestra una confirmación de éxito.

  #### Ruta Feliz
  DADO que un administrador registra un usuario sin asignar rol
  CUANDO guarda el registro
  ENTONCES el sistema asigna por defecto el rol "Operador Logístico".

  #### Ruta Infeliz
  DADO que un administrador intenta registrar un usuario con un correo ya existente
  CUANDO envía el formulario
  ENTONCES el sistema rechaza la operación y muestra "El correo electrónico ya se encuentra registrado".

---

### RF-003: Control de Acceso por Rol (RBAC)
- **Descripción Atómica:** El sistema debe restringir el acceso a cada módulo según el rol del usuario (Administrador, Operador Logístico, Gerente), impidiendo el uso de funciones no autorizadas.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**
  #### Ruta Gold
  DADO que un operador logístico está autenticado
  CUANDO intenta acceder a un módulo restringido a administrador
  ENTONCES el sistema deniega el acceso y muestra "No tiene permisos para acceder a esta sección".

  #### Ruta Feliz
  DADO que un administrador está autenticado
  CUANDO accede a cualquier módulo del sistema
  ENTONCES el sistema permite el acceso a todas las funcionalidades.

  #### Ruta Infeliz
  DADO que un usuario no autenticado intenta acceder a una sección protegida
  CUANDO realiza la solicitud
  ENTONCES el sistema rechaza el acceso y redirige a la página de inicio de sesión.

---

### RF-004: Registro de Puntos de Entrega
- **Descripción Atómica:** El sistema debe permitir al operador logístico registrar puntos de entrega mediante dirección o coordenadas geográficas, junto con el peso del paquete y el nombre del destinatario.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**
  #### Ruta Gold
  DADO que un operador logístico accede al módulo de registro de puntos
  CUANDO ingresa la dirección, peso y destinatario, y guarda
  ENTONCES el sistema valida la ubicación, crea el punto de entrega y lo agrega a la lista de puntos disponibles para planificar.

  #### Ruta Feliz
  DADO que un operador logístico registra varios puntos en una misma sesión
  CUANDO agrega cada punto
  ENTONCES el sistema acumula los puntos en una lista de planificación y muestra el total registrado.

  #### Ruta Infeliz
  DADO que un operador logístico ingresa una dirección que no puede geocodificarse
  CUANDO intenta guardar el punto
  ENTONCES el sistema rechaza el registro y muestra "La dirección ingresada no es válida".

---

### RF-005: Gestión de Puntos de Entrega
- **Descripción Atómica:** El sistema debe permitir al operador logístico modificar y eliminar puntos de entrega que aún no formen parte de una ruta confirmada.
- **Prioridad:** Media
- **Criterios de Aceptación (Gherkin / BDD):**
  #### Ruta Gold
  DADO que un operador logístico selecciona un punto de entrega sin ruta asignada
  CUANDO modifica la dirección o el peso y guarda
  ENTONCES el sistema actualiza los datos del punto.

  #### Ruta Feliz
  DADO que un operador logístico selecciona un punto de entrega sin ruta asignada
  CUANDO confirma su eliminación
  ENTONCES el sistema elimina el punto de la lista de planificación.

  #### Ruta Infeliz
  DADO que un operador logístico intenta eliminar un punto que ya pertenece a una ruta confirmada
  CUANDO intenta eliminarlo
  ENTONCES el sistema deniega la acción y muestra "No se puede eliminar un punto incluido en una ruta confirmada".

---

### RF-006: Generación de Ruta Optimizada
- **Descripción Atómica:** El sistema debe calcular automáticamente una ruta optimizada para los puntos de entrega registrados, considerando el centro de distribución como punto de inicio y minimizando la distancia total recorrida.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**
  #### Ruta Gold
  DADO que existen al menos dos puntos de entrega válidos registrados
  CUANDO el operador logístico ejecuta "Generar Ruta Optimizada"
  ENTONCES el sistema calcula la secuencia de visitas de menor distancia, comenzando en el centro de distribución, y presenta un resumen con la distancia total y el tiempo estimado.

  #### Ruta Feliz
  DADO que existe una única solución razonable para los puntos registrados
  CUANDO el sistema ejecuta el cálculo
  ENTONCES el sistema genera la ruta y la deja disponible para su validación y visualización.

  #### Ruta Infeliz
  DADO que no existe por lo menos un punto de entrega válido
  CUANDO el operador intenta generar la ruta
  ENTONCES el sistema no genera ninguna ruta y muestra "No hay puntos de entrega suficientes para planificar una ruta".

---

### RF-007: Estimación de Restricciones de Capacidad
- **Descripción Atómica:** El sistema debe verificar que la carga total de los puntos asignados no supere la capacidad máxima del vehículo configurado, impidiendo la generación de una ruta que exceda dicha capacidad.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**
  #### Ruta Gold
  DADO que un vehículo tiene capacidad máxima de 800 kg y los puntos suman 600 kg
  CUANDO se ejecuta la generación de ruta
  ENTONCES el sistema permite la ruta porque la carga no supera la capacidad.

  #### Ruta Feliz
  DADO que la carga de los puntos puede dividirse en más de una ruta
  CUANDO el sistema evalúa la asignación
  ENTONCES el sistema agrupa los puntos en tantas rutas como sean necesarias respetando la capacidad de cada vehículo.

  #### Ruta Infeliz
  DADO que la carga total de los puntos excede la capacidad del único vehículo disponible
  CUANDO se ejecuta la generación de ruta
  ENTONCES el sistema genera la ruta con los puntos que caben en el vehículo y marca los restantes como pendientes con un mensaje de advertencia de capacidad insuficiente.

---

### RF-008: Comparación de Impacto Ambiental (CO₂)
- **Descripción Atómica:** El sistema debe estimar y mostrar una comparación entre la ruta optimizada y una ruta no optimizada (orden de ingreso original) en términos de distancia, tiempo y emisiones de CO₂.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**
  #### Ruta Gold
  DADO que un operador logístico ha generado una ruta optimizada
  CUANDO el sistema presenta el resumen de la ruta
  ENTONCES el sistema muestra lado a lado la ruta optimizada y la no optimizada, evidenciando el porcentaje de ahorro de distancia y CO₂.

  #### Ruta Feliz
  DADO que la ruta optimizada logra una reducción de distancia
  CUANDO se muestra la comparación
  ENTONCES el sistema resalta visualmente el ahorro logrado con indicadores claros.

  #### Ruta Infeliz
  DADO que la ruta optimizada no logra una mejora significativa
  CUANDO se muestra la comparación
  ENTONCES el sistema muestra ambos resultados fielmente sin ocultar que la mejora es marginal.

---

### RF-009: Visualización de la Ruta en Mapa
- **Descripción Atómica:** El sistema debe representar la ruta calculada sobre un mapa interactivo, mostrando el origen (centro de distribución), los puntos de entrega en orden de visita y el recorrido trazado.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**
  #### Ruta Gold
  DADO que se ha generado una ruta optimizada
  CUANDO el operador accede a la visualización de la ruta
  ENTONCES el sistema muestra un mapa con el centro de distribución, los puntos de entrega numerados en orden y la línea del recorrido.

  #### Ruta Feliz
  DADO que la ruta tiene varios puntos de entrega
  CUANDO el operador interactúa con el mapa
  ENTONCES el sistema permite la navegación y muestra información de cada parada al seleccionar su marcador.

  #### Ruta Infeliz
  DADO que el servicio de mapas externo no responde
  CUANDO el operador intenta ver la ruta en el mapa
  ENTONCES el sistema muestra la ruta en formato de lista ordenada de direcciones y un mensaje de "Servicio de mapas temporalmente no disponible".

---

### RF-010: Confirmación y Gestión de Rutas (Panel del Operador)
- **Descripción Atómica:** El sistema debe permitir al operador logístico confirmar una ruta calculada y conservarla en un panel de rutas donde pueda consultarla o eliminarla.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**
  #### Ruta Gold
  DADO que una ruta optimizada ha sido generada
  CUANDO el operador revisa el resultado y presiona "Confirmar Ruta"
  ENTONCES el sistema guarda la ruta en el panel de rutas con su estado "Confirmada".

  #### Ruta Feliz
  DADO que una ruta no satisface las necesidades del operador
  CUANDO presiona "Descartar" en lugar de confirmar
  ENTONCES el sistema descarta la ruta propuesta y mantiene los puntos disponibles para replanificar.

  #### Ruta Infeliz
  DADO que un operador intenta eliminar una ruta con entregas ya marcadas como completadas
  CUANDO intenta eliminarla desde el panel
  ENTONCES el sistema deniega la eliminación y muestra "No se puede eliminar una ruta con entregas completadas".

---

### RF-011: Visualización de Rutas Históricas
- **Descripción Atómica:** El sistema debe permitir al operador logístico y al gerente consultar el listado de rutas generadas, con su estado, distancia total y fecha de creación.
- **Prioridad:** Media
- **Criterios de Aceptación (Gherkin / BDD):**
  #### Ruta Gold
  DADO que un operador logístico accede al panel de rutas
  CUANDO se carga la página
  ENTONCES el sistema muestra una tabla con las rutas generadas, incluyendo identificación, fecha, cantidad de puntos, distancia y estado.

  #### Ruta Feliz
  DADO que un gerente accede al panel de rutas
  CUANDO selecciona una ruta específica
  ENTONCES el sistema muestra el detalle de la ruta con su recorrido y las entregas asociadas.

  #### Ruta Infeliz
  DADO que no existen rutas registradas
  CUANDO el usuario accede al panel de rutas
  ENTONCES el sistema muestra "No existen rutas registradas".

---

### RF-012: Visualización de Indicadores de Sostenibilidad
- **Descripción Atómica:** El sistema debe calcular y mostrar al gerente las emisiones totales estimadas de CO₂ y el ahorro estimado logrado con las rutas optimizadas respecto a las rutas no optimizadas.
- **Prioridad:** Media
- **Criterios de Aceptación (Gherkin / BDD):**
  #### Ruta Gold
  DADO que un gerente accede al módulo de indicadores de sostenibilidad
  CUANDO se carga la página
  ENTONCES el sistema muestra las emisiones totales, las emisiones por entrega y el ahorro porcentual de CO₂ respecto a rutas no optimizadas.

  #### Ruta Feliz
  DADO que existen rutas optimizadas y no optimizadas en el historial
  CUANDO el gerente consulta los indicadores
  ENTONCES el sistema muestra la comparación evidenciando la reducción de emisiones lograda.

  #### Ruta Infeliz
  DADO que no existen rutas con datos de emisiones
  CUANDO el gerente accede al módulo
  ENTONCES el sistema muestra "No hay datos de sostenibilidad disponibles para generar indicadores".

---

### RF-013: Panel de Indicadores del Gerente (Dashboard)
- **Descripción Atómica:** El sistema debe mostrar al gerente un panel con resumen de indicadores clave: cantidad de rutas generadas, distancia total recorrida y emisiones estimadas de CO₂.
- **Prioridad:** Media
- **Criterios de Aceptación (Gherkin / BDD):**
  #### Ruta Gold
  DADO que un gerente se autentica exitosamente
  CUANDO el sistema redirige al panel del gerente
  ENTONCES el panel muestra los indicadores de distancia total, cantidad de rutas y emisiones estimadas basados en las rutas registradas.

  #### Ruta Feliz
  DADO que existen rutas confirmadas
  CUANDO el gerente consulta el panel
  ENTONCES el sistema actualiza los indicadores con los datos más recientes.

  #### Ruta Infeliz
  DADO que no hay rutas registradas
  CUANDO el gerente accede al panel
  ENTONCES el sistema muestra los indicadores en cero con el mensaje "No hay datos disponibles para generar indicadores".

---

### RF-014: Cierre de Sesión
- **Descripción Atómica:** El sistema debe permitir al usuario autenticado cerrar su sesión de forma explícita, invalidando el acceso actual y redirigiendo a la página de inicio de sesión.
- **Prioridad:** Baja
- **Criterios de Aceptación (Gherkin / BDD):**
  #### Ruta Gold
  DADO que un usuario tiene una sesión activa
  CUANDO presiona "Cerrar Sesión"
  ENTONCES el sistema invalida la sesión y redirige a la página de inicio de sesión.

  #### Ruta Feliz
  DADO que un usuario cierra el navegador con una sesión activa
  CUANDO intenta acceder nuevamente tiempo después
  ENTONCES el sistema valida la expiración de la sesión y solicita iniciar sesión nuevamente si corresponde.

  #### Ruta Infeliz
  DADO que un usuario intenta usar una sesión ya invalidada
  CUANDO realiza una acción protegida
  ENTONCES el sistema rechaza la acción y redirige al inicio de sesión.

## 5. Supuestos y Dependencias

| ID | Descripción |
|---|---|
| SUP-RF-01 | El motor de optimización utilizará una heurística simple (p. ej. vecino más cercano) que entrega una buena solución en tiempo razonable, sin requerir optimalidad matemática. |
| SUP-RF-02 | La API gratuita de geolocalización/mapas estará disponible dentro de su cuota durante las demostraciones del PMV. |
| SUP-RF-03 | La generación de una ruta para el escenario base del PMV (hasta ~20 puntos) no excederá unos pocos segundos de cómputo. |
| SUP-RF-04 | Los tiempos de recorrido se estiman a partir de distancias; no se considerará tráfico en tiempo real en esta versión. |
| SUP-RF-05 | El PMV se valida con casos de prueba que permiten demostrar la reducción de distancia (≥15%) y de CO₂ (≥10%) frente a la ruta no optimizada. |
