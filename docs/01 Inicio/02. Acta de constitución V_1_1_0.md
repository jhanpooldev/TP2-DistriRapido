## 1. Propósito y Justificación del Proyecto

DistriRápido S.A.C. es una empresa de distribución y reparto de última milla que opera en Lima Metropolitana. Actualmente, la planificación de sus rutas de entrega se realiza de forma manual o mediante herramientas genéricas de mapas que no consideran criterios de sostenibilidad ni la optimización conjunta de múltiples paradas, lo que genera sobrecostos de combustible, tiempos de entrega prolongados y una huella de carbono innecesariamente alta.

El proyecto **EcoLogística Lima** nace como respuesta a esta problemática: desarrollar un Producto Mínimo Viable (PMV) de una aplicación web que optimice las rutas de reparto considerando distancia, tiempo estimado e impacto ambiental, permitiendo a DistriRápido S.A.C. reducir costos operativos, mejorar sus tiempos de entrega y avanzar hacia una operación logística más sostenible.

Desde la perspectiva académica, el proyecto permite al equipo aplicar de forma integrada los conocimientos de ingeniería de software, gestión de proyectos bajo un enfoque híbrido, control de versiones y arquitectura de software adquiridos en el curso Taller de Proyectos 2.

## 2. Objetivos Medibles (Criterios SMART)

| Dimensión | Objetivo |
|---|---|
| **Alcance** | Desarrollar un Producto Mínimo Viable (PMV) funcional que permita registrar puntos de entrega, calcular una ruta optimizada (distancia, tiempo e impacto ambiental estimado) y visualizarla en un mapa interactivo, estructurado en frontend y backend separados. |
| **Cronograma** | Completar y entregar el PMV etiquetado como versión **v1.0.0** dentro del periodo fijo de 12 semanas del curso, con cierre estimado el **15/11/2026** (fecha referencial, sujeta al calendario oficial del curso). |
| **Costo** | Ejecutar el proyecto sin exceder el presupuesto estimado (ver sección 6), manteniendo en el mínimo posible el gasto en infraestructura mediante el uso de herramientas y niveles gratuitos (*free tier*). |
| **Calidad** | Entregar un PMV sin errores críticos en el flujo principal (registro de puntos → cálculo de ruta → visualización), superando al menos el **90%** de los casos de prueba funcionales definidos por el equipo, con documentación completa según PMBOK en la carpeta `docs/` y cumplimiento del 100% de la nomenclatura y estructura exigida por la consigna del curso. |

## 3. Requisitos de Alto Nivel

### 3.1. Funcionalidades clave

| ID | Requisito |
|---|---|
| RF-01 | Registro de puntos de entrega (dirección o coordenadas geográficas). |
| RF-02 | Cálculo automático de una ruta optimizada entre los puntos registrados, considerando distancia y/o tiempo estimado. |
| RF-03 | Estimación comparativa del impacto ambiental (CO₂) entre la ruta optimizada y una ruta no optimizada (orden de ingreso original). |
| RF-04 | Visualización interactiva de la ruta calculada sobre un mapa. |
| RF-05 | Panel básico para que el operador logístico gestione (cree, edite, elimine) sus rutas de reparto. |

### 3.2. Limitaciones técnicas iniciales

| ID | Limitación |
|---|---|
| LT-01 | Dependencia de APIs externas gratuitas de mapas/geolocalización, sujetas a límites de cuota. |
| LT-02 | No se contempla integración en tiempo real con dispositivos GPS de los vehículos (fuera del alcance del PMV). |
| LT-03 | No incluye módulos de facturación, pagos ni gestión financiera. |
| LT-04 | Optimizado para navegadores web modernos de escritorio; no se garantiza una experiencia responsiva completa en dispositivos móviles en esta primera versión. |
| LT-05 | El algoritmo de optimización utilizará heurísticas; no garantiza la solución matemáticamente óptima, sino una solución de buena calidad en un tiempo de cómputo razonable. |

### 3.3. Requisitos No Funcionales (RNF)

*(Sección incorporada en la versión 1.1.0 — ver Historial de Control de Cambios, sección 8)*

| ID | Requisito No Funcional |
|---|---|
| RNF-01 | El sistema debe generar una ruta optimizada en menos de 5 segundos para hasta 20 puntos de entrega. |
| RNF-02 | El acceso al sistema debe requerir autenticación, y toda comunicación debe viajar cifrada (HTTPS). |
| RNF-03 | Todo cambio integrado a la rama principal debe desplegarse automáticamente a un ambiente de Staging. |
