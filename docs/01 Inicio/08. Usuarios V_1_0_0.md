# Documento 03: Identificación y Perfiles de Usuarios

**Proyecto:** EcoLogística Lima – Optimizador de Rutas Sostenibles para DistriRápido S.A.C.
**Versión:** 1.0.0 | **Fecha:** 27/08/2026

## 1. Matriz de Roles y Actores

### 1.1 Actores Directos

- **Nombre del Rol / Perfil:** Administrador del Sistema
- **Tipo de Actor:** Directo (Humano)
- **Descripción:** Es la persona encargada de mantener la plataforma funcionando correctamente. Se encarga de dar de alta a los usuarios del equipo, asignarles su rol y definir los datos básicos de la operación (como la ubicación del centro de distribución). También es la persona que ve todas las funcionalidades sin límites.
- **Nivel Técnico / Alfabetización Digital:** Medio
- **Objetivos Principales:** Que todos los integrantes del equipo tengan acceso al sistema con su usuario y contraseña, y que los datos base estén correctamente configurados para que el equipo pueda trabajar.
- **Canal de Interacción:** UI Web (panel de administración)

---

- **Nombre del Rol / Perfil:** Operador Logístico
- **Tipo de Actor:** Directo (Humano)
- **Descripción:** Es la persona que usa el sistema a diario. Su trabajo es registrar los puntos de entrega, generar la ruta optimizada, ver la comparación de CO₂ y confirmar la ruta para el reparto. Es el rol central del PMV y el que más usa la plataforma.
- **Nivel Técnico / Alfabetización Digital:** Medio
- **Objetivos Principales:** Armar una ruta de reparto en pocos pasos, con la menor distancia posible y el menor impacto ambiental, para optimizar el trabajo de distribución de DistriRápido S.A.C.
- **Canal de Interacción:** UI Web (panel del operador)

---

- **Nombre del Rol / Perfil:** Gerente
- **Tipo de Actor:** Directo (Humano)
- **Descripción:** Es la persona de la gerencia que revisa los resultados de la operación. No registra datos operativos, sino que consulta los indicadores: cantidad de rutas generadas, distancia total recorrida y emisiones estimadas de CO₂. Su intención es verificar que la optimización esté dando buenos resultados.
- **Nivel Técnico / Alfabetización Digital:** Medio
- **Objetivos Principales:** Visualizar de forma clara y rápida cómo está rindiendo la flota y cuánto se está ahorrando en distancia y emisiones gracias al sistema.
- **Canal de Interacción:** UI Web (panel de lectura / reporte)

---

### 1.2 Actores Indirectos

- **Nombre del Rol / Perfil:** Docente del curso (Evaluador / Sponsor Académico)
- **Tipo de Actor:** Indirecto (Humano)
- **Descripción:** Es quien evalúa el proyecto. Revisa la documentación en `docs/`, observa la demostración funcional del PMV y verifica el cumplimiento de la consigna (repositorio, ramas, versionado, video). No opera el sistema, pero valida que cumpla los requisitos del curso.
- **Puntos de Integración / Consumo:** Revisión del repositorio GitHub, documentación Markdown, video demostrativo y demo funcional.

---

- **Nombre del Rol / Perfil:** API de Mapas / Geolocalización (Sistema de Terceros)
- **Tipo de Actor:** Indirecto (Sistema)
- **Descripción:** Proveedor externo de mapas y geolocalización que el sistema consulta para validar direcciones, calcular distancias y mostrar la ruta sobre un mapa. Es una interacción automatizada de tipo cliente-servidor.
- **Puntos de Integración / Consumo:** API REST externa (nivel gratuito), consultada desde el Backend.

---

- **Nombre del Rol / Perfil:** Gerencia de Operaciones de DistriRápido S.A.C. (Cliente simulado)
- **Tipo de Actor:** Indirecto (Humano)
- **Descripción:** Representa al cliente que recibirá el sistema. En el contexto académico es una simulación; su interés es que el PMV resuelva la problemática de la planificación manual de rutas. Participa validando la utilidad percibida del producto, pero no opera el sistema directamente.
- **Puntos de Integración / Consumo:** Demostraciones funcionales y retroalimentación sobre el uso del PMV.

## 3. Matriz de Control de Acceso (RBAC / ABAC)

**Leyenda de permisos:**
- **C** = Crear (Crear/Registrar nuevos datos)
- **R** = Leer (Consultar/Visualizar datos)
- **U** = Actualizar (Modificar datos existentes)
- **D** = Eliminar/Delete (Eliminar datos)
- **Sin Acceso** = El rol no puede realizar ninguna operación sobre el módulo

## 4. Notas de Diseño del Control de Acceso

| ID | Nota |
|---|---|
| NOT-01 | El control de acceso se basa en **RBAC** (permisos según el rol asignado), que es un modelo simple y suficiente para el alcance académico del PMV. No se requiere el modelo ABAC (atributos complejos) en esta versión. |
| NOT-02 | La eliminación de puntos de entrega (D) está restringida a puntos que **no** formen parte de una ruta confirmada. Los puntos incluidos en rutas confirmadas no pueden eliminarse para conservar la integridad del historial. |
| NOT-03 | El Docente del curso, la Gerencia simulada y la API de Mapas son actores **indirectos**: no tienen credenciales de acceso al sistema. Su interacción se da a través de la revisión de documentación, demos y consumo de API externa, respectivamente. |
| NOT-04 | Cada usuario solo puede modificar su propio perfil; no puede modificar la información de otros usuarios salvo el Administrador. |
| NOT-05 | La exportación de datos y la eliminación física de registros quedan fuera del alcance del PMV y se marcan como Sin Acceso para todos los roles, a fin de mantener el sistema simple y seguro dentro del tiempo del curso. |

## 6. Supuestos

| ID | Descripción |
|---|---|
| SUP-01 | Cada usuario del equipo tendrá una cuenta propia con su rol asignado por el Administrador. |
| SUP-02 | En el PMV el acceso se valida mediante roles fijos (Administrador, Operador Logístico, Gerente); no se contempla la personalización granular de permisos por atributo (ABAC). |
| SUP-03 | Los actores indirectos (docente, gerencia simulada, API de mapas) no requieren cuentas de usuario dentro del sistema. |
