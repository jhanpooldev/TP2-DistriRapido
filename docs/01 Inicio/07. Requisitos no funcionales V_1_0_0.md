# Documento 02: Requisitos No Funcionales (RNF)

**Proyecto:** EcoLogística Lima – Optimizador de Rutas Sostenibles para DistriRápido S.A.C.
**Versión:** 1.0.0 | **Fecha:** 27/08/2026

---

## 1. Introducción y Marco de Atributos de Calidad

Los requisitos no funcionales (RNF) definen los atributos de calidad que debe poseer el sistema **EcoLogística Lima** para que el Producto Mínimo Viable (PMV) sea estable, predecible y demostrable dentro de un contexto académico de doce semanas. La especificación se organiza bajo las categorías del estándar **ISO/IEC 25010**, garantizando que los atributos de rendimiento, seguridad, disponibilidad, usabilidad y mantenibilidad se describan con umbrales cuantitativos verificables en lugar de adjetivos subjetivos. Este enfoque asegura que el equipo, integrado por estudiantes de décimo ciclo, pueda validar objetivamente el cumplimiento de cada atributo mediante métricas SMART y pruebas concretas.

Dada la naturaleza académica y el alcance reducido del PMV, los umbrales de calidad se definen de forma **alcanzable y medible** dentro del entorno de demostración, sin comprometer la solidez del flujo principal (registro de puntos → generación de ruta → visualización en mapa → comparación de CO₂). Los valores de referencia (P95, segundos, porcentajes) se establecen tomando como base el escenario base del PMV documentado en el SPECS: hasta ~20 puntos de entrega, tiempos de generación de pocos segundos y operación en un entorno de hosting gratuito. Cada RNF se expresará como un Escenario de Calidad (Fuente → Estímulo → Entorno → Artefacto → Respuesta → Medida) conforme a la notación de **arc42**, permitiendo que todos los interesados comprendan el comportamiento esperado del sistema bajo condiciones específicas.

## 2. Matriz de Escenarios de Calidad y Métricas SMART

| ID | Categoría ISO 25010 | Escenario de Calidad (Fuente -> Estímulo -> Entorno -> Artefacto -> Respuesta -> Medida SLA) |
|---|---|---|
| **RNF-001** | Rendimiento y Eficiencia | **Fuente:** Operador logístico.<br>**Estímulo:** Genera una ruta optimizada con hasta 20 puntos de entrega.<br>**Entorno:** Operación normal sobre infraestructura de hosting gratuito, sin carga concurrente significativa.<br>**Artefacto:** Módulo de Optimización de Rutas (Backend).<br>**Respuesta:** Calcular la secuencia óptima y retornar el resultado al frontend.<br>**Medida:** Tiempo de generación de ruta ≤ **5 segundos** (P95) para conjuntos de hasta 20 puntos; para el escenario completo del PMV (50 puntos) ≤ **50 segundos** (P95), según requisito no funcional del SPECS. |
| **RNF-002** | Rendimiento y Eficiencia | **Fuente:** Operador logístico.<br>**Estímulo:** Realiza una petición de consulta (listado de puntos, rutas o indicadores).<br>**Entorno:** Operación normal de un único usuario.<br>**Artefacto:** API REST (Backend) + Frontend.<br>**Respuesta:** Procesar la solicitud, consultar datos y devolver el payload al navegador.<br>**Medida:** Latencia de respuesta del servicio ≤ **1.5 segundos** (P95) para consultas de lectura en el escenario base (≤ 50 registros por listado). |
| **RNF-003** | Rendimiento y Eficiencia | **Fuente:** Usuario concurrente.<br>**Estímulo:** Accede simultáneamente a las funcionalidades de consulta del sistema.<br>**Entorno:** Demostración con hasta 5 usuarios concurrentes sobre hosting gratuito.<br>**Artefacto:** API REST y servicio de autenticación.<br>**Respuesta:** Atender todas las peticiones y retornar los payloads sin pérdida de datos.<br>**Medida:** Capacidad mínima de **10 transacciones por segundo (TPS)** y error de respuesta ≤ **1%** de las peticiones bajo la carga de demostración. |
| **RNF-004** | Seguridad | **Fuente:** Atacante externo / Usuario no autorizado.<br>**Estímulo:** Intenta acceder a un módulo sin autenticación o sin el rol correspondiente.<br>**Entorno:** Entorno de producción (demostración).<br>**Artefacto:** Capa de Autenticación y Control de Acceso por Rol (RBAC).<br>**Respuesta:** Denegar el acceso, no exponer datos protegidos y registrar el intento.<br>**Medida:** **0%** de peticiones no autorizadas completadas con éxito; acceso denegado con respuesta HTTP 401/403 en **< 300 ms**. |
| **RNF-005** | Seguridad | **Fuente:** Atacante externo.<br>**Estímulo:** Intenta comprometer el sistema mediante inyección de código o consultas maliciosas.<br>**Entorno:** Entorno de producción (demostración).<br>**Artefacto:** Capa de validación de datos (Backend).<br>**Respuesta:** Validar y rechazar la entrada maliciosa antes de procesarla.<br>**Medida:** **0%** de vulnerabilidades explotables correspondientes a **OWASP Top 10** (inyección, XSS, control de acceso roto) ejecutables en el PMV; 100% de entradas validadas en el lado del servidor. |
| **RNF-006** | Seguridad | **Fuente:** Usuario / Proceso interno.<br>**Estímulo:** Guarda o transmite credenciales e información sensible.<br>**Entorno:** Almacenamiento y transmisión de datos.<br>**Artefacto:** Módulo de Autenticación y Base de Datos.<br>**Respuesta:** Procesar y almacenar las credenciales sin exponer información de forma legible.<br>**Medida:** 100% de contraseñas almacenadas con **hasheado irreversible (bcrypt)**; 100% del tráfico del frontend hacia la API transmitido mediante **HTTPS** en el entorno de demostración. |
| **RNF-007** | Disponibilidad y Confiabilidad | **Fuente:** Proveedor de servicio de hosting / API de mapas externa.<br>**Estímulo:** Caída temporal del servicio o agotamiento de la cuota de la API de geolocalización.<br>**Entorno:** Operación de demostración.<br>**Artefacto:** Frontend / Backend / Servicio de mapas.<br>**Respuesta:** Mantener la operación del flujo principal; degradar la visualización del mapa a formato tabular y retornar error controlado.<br>**Medida:** Disponibilidad global del PMV ≥ **95%** durante las ventanas de demostración; el flujo de generación de ruta debe poder completarse sin el mapa (modo degradado) en el **100%** de los casos. |
| **RNF-008** | Disponibilidad y Confiabilidad | **Fuente:** Usuario.<br>**Estímulo:** Interrumpe la conexión durante una operación dentro del flujo principal.<br>**Entorno:** Operación de demostración con señal inestable.<br>**Artefacto:** API REST y Frontend.<br>**Respuesta:** Mantener la consistencia de los datos; no persistir operaciones incompletas y permitir reintento.<br>**Medida:** Pérdida de datos de transacciones completadas = **0%**; el sistema permanece en estado consistente tras una interrupción y permite reintentar la operación sin duplicar registros. |
| **RNF-009** | Usabilidad | **Fuente:** Operador logístico / Gerente.<br>**Estímulo:** Ejecuta el flujo principal de generación de una ruta.<br>**Entorno:** Interfaz web de escritorio en navegador moderno.<br>**Artefacto:** Frontend (Interfaz de Usuario).<br>**Respuesta:** Guiar al usuario mediante pasos claros y mensajes de retroalimentación.<br>**Medida:** El operador debe poder completar la generación de una ruta en **3 pasos o menos** (objetivo KPI de la Visión); el tiempo promedio de completar el flujo principal ≤ **3 minutos** para un usuario con experiencia mínima. |
| **RNF-010** | Usabilidad y Accesibilidad | **Fuente:** Usuario final (incluido con discapacidad visual).<br>**Estímulo:** Interactúa con los formularios, botones y mensajes del sistema.<br>**Entorno:** Navegador web de escritorio.<br>**Artefacto:** Frontend (componentes de interfaz y formularios).<br>**Respuesta:** Presentar una interfaz legible, con etiquetas descriptivas y contraste adecuado.<br>**Medida:** Cumplimiento del **nivel AA de WCAG 2.1** en los controles de formulario y mensajes de error (textos de etiqueta y contraste ≥ 4.5:1); **100%** de los campos de formulario con etiqueta asociada. |
| **RNF-011** | Mantenibilidad | **Fuente:** Equipo de desarrollo.<br>**Estímulo:** Modifica o corrige una funcionalidad dentro de un módulo del sistema.<br>**Entorno:** Entorno de desarrollo, repositorio con control de versiones.<br>**Artefacto:** Código fuente de Frontend y Backend.<br>**Respuesta:** Permitir localizar y modificar el cambio sin afectar módulos no relacionados.<br>**Medida:** Estructura de código organizada (separación backend/frontend y arquitectura por capas); cobertura de pruebas automatizadas global ≥ **70%** (≥ **80%** en módulos de validación), según criterios de aceptación del SPECS. |
| **RNF-012** | Mantenibilidad y Modificabilidad | **Fuente:** Equipo de desarrollo.<br>**Estímulo:** Agrega una nueva funcionalidad o API al sistema.<br>**Entorno:** Entorno de desarrollo y repositorio Git.<br>**Artefacto:** Arquitectura de la aplicación.<br>**Respuesta:** Incorporar el cambio con bajo impacto sobre el resto del sistema.<br>**Medida:** La arquitectura modular permite **acoplamiento bajo**; documentación actualizada (README + docs/) que refleja el cambio. Cumplimiento de la estructura exigida por la consigna (frontend/backend separados, .gitignore presente). |
| **RNF-013** | Compatibilidad | **Fuente:** Usuario final.<br>**Estímulo:** Abre el sistema en un navegador de escritorio moderno.<br>**Entorno:** Navegadores Chrome, Edge y Firefox en sus versiones recientes.<br>**Artefacto:** Frontend (SPA).<br>**Respuesta:** Renderizar y operar el sistema de forma consistente en los navegadores soportados.<br>**Medida:** **100%** de las funcionalidades principales operativas en los tres navegadores soportados (Chrome, Edge, Firefox) sin errores de renderizado críticos. |
| **RNF-014** | Portabilidad | **Fuente:** Equipo de desarrollo / Entorno de despliegue.<br>**Estímulo:** Despliega el sistema en una plataforma de hosting gratuita.<br>**Entorno:** Entorno de producción de demostración en la nube.<br>**Artefacto:** Aplicación completa (Backend, Frontend, Base de Datos).<br>**Respuesta:** Ejecutarse correctamente en el entorno de hosting sin configuración específica del equipo de desarrollo.<br>**Medida:** Despliegue reproducible mediante **variables de entorno** para datos sensibles y **archivo **`.gitignore`** completo; el PMV debe desplegarse y operar en el proveedor gratuito (0% de gasto en infraestructura, según Acta de Constitución). |
| **RNF-015** | Resiliencia (Manejo de Errores) | **Fuente:** Usuario / API externa.<br>**Estímulo:** Ingresa datos inválidos o se produce un error durante la optimización.<br>**Entorno:** Operación normal.<br>**Artefacto:** Capa de validación y motor de optimización.<br>**Respuesta:** Detectar el error, mantener el estado consistente y devolver un mensaje de error explícito.<br>**Medida:** **100%** de los errores esperados manejados con mensajes descriptivos; estado de los datos permanece consistente (sin registros parciales) tras cualquier error controlado. |

## 3. Resumen de Requisitos No Funcionales

| Atributo de Calidad (ISO 25010) | RNF Asociados | Umbral Clave Principal |
|---|:---:|---|
| Rendimiento y Eficiencia | RNF-001, RNF-002, RNF-003 | Generación de ruta ≤ 5 s (P95, 20 puntos); latencia consulta ≤ 1.5 s (P95); ≥ 10 TPS |
| Seguridad | RNF-004, RNF-005, RNF-006 | 0% accesos no autorizados; 0% vulnerabilidades OWASP Top 10; bcrypt + HTTPS 100% |
| Disponibilidad y Confiabilidad | RNF-007, RNF-008 | Disponibilidad ≥ 95%; pérdida de datos 0% |
| Usabilidad y Accesibilidad | RNF-009, RNF-010 | Ruta en ≤ 3 pasos; WCAG 2.1 nivel AA |
| Mantenibilidad | RNF-011, RNF-012 | Cobertura global ≥ 70% (validación ≥ 80%) |
| Compatibilidad | RNF-013 | 100% funcional en los 3 navegadores soportados |
| Portabilidad | RNF-014 | Despliegue en hosting gratuito reproducible |
| Resiliencia | RNF-015 | 100% de errores manejados; estado consistente |

## 4. Notas y Supuestos

| ID | Descripción |
|---|---|
| NOT-01 | Los umbrales de rendimiento (RNF-001 a RNF-003) se establecen para el entorno de demostración sobre hosting gratuito y sin carga concurrente elevada, en línea con el alcance académico del proyecto. No aplican exigencia de alta disponibilidad de nivel empresarial. |
| NOT-02 | La métrica de accesibilidad WCAG 2.1 nivel AA (RNF-010) se centra en los elementos esenciales del PMV (formularios, etiquetas, contraste y mensajes de error), sin exigir la totalidad de las pautas aplicables a sistemas complejos. |
| NOT-03 | Los valores de cobertura de pruebas (RNF-011) se toman de los criterios de aceptación del SPECS: cobertura global ≥ 70% y módulos de validación ≥ 80%, verificables mediante las herramientas de prueba del proyecto. |
| NOT-04 | El despliegue está limitado al nivel gratuito (free tier) de un proveedor cloud, sin costos de infraestructura, conforme al presupuesto de S/ 0.00 definido en el Acta de Constitución. |
| NOT-05 | Los RNF se orientan a validar el cumplimiento durante ventanas de demostración y pruebas del proyecto; no constituyen compromisos de operación continua 24/7 de nivel productivo. |
